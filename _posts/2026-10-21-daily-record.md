## 1. 在一个旧的模型项目上，结合官方仓库，怎么样把原来的模型在新的数据集上再训练

- 有的时候论文的配置和仓库的配置会出现冲突，比如说论文里面设置的步数是100K，仓库里面设置的是500K，如果不是需要完全复刻论文的话，只是为了把原来的基础模型在我们的数据集上再训练一下的话，那么还是建议以仓库里面的为主，毕竟仓库里面可能是真的跑通了的，训练成功的概率会更大一点的

## 2. batch_size的理解和说明

- `batch_size` 指的是一次处理多少个样本，再根据这些样本的平均损失，计算梯度有些论文里面的卡的配置是比较豪华的，有时候batch_size是会很大的，我们打个比方，是64，我们自己的卡可能没有这么大的显存，就可以使用一些操作获得等效的64的batch_size，比如说，我们用两张卡，每张卡放4个样本，累计8次梯度之后更新参数，那么实际有效batch_size就是2\*4\*8=64

  ```txt
  effective_batch_size =
      per_device_batch_size
      × gradient_accumulation_steps
      × GPU 数量
  ```

## 3. 配置文件ymal/yml，train.sh，train.py等文件之间的关系和如何使用

- ```text
  .sh       = 启动脚本，负责组织和执行训练命令
  train.py  = 通常是训练程序的入口
  .yaml     = 保存模型、数据和训练超参数的配置文件
  --参数     = 命令行参数，用来指定或覆盖配置
  ```

## 4. 训练的时候出现训练崩溃现象，loss爆炸了

导致训练时候出现训练崩溃，loss爆炸上升的原因有很多：

1. 学习率过高（但是现在一般都是固定学习率了的，所以出现了这个问题，想要修复，估计是不太容易了的）
2. 数据格式的问题，有时候官方仓库的数据是一种格式，输入维度和处理过程都不太一样的，我们尝试在我们自己的数据集上训练的话，需要解决这些问题的，但是可能一次又无法彻底解决，所以会出现训练过程中loss爆炸上升的问题

## 5. 在训练的时候面对训练崩溃的问题，可以修改学习率续训的吗？

在训练的过程中，可能会出现训练崩溃的问题，这个时候，loss回升，有可能就是因为学习率过高的问题，这个时候，可以考虑，先使用最近保存的一个训练点checkpoint，然后的话，修改学习率为更小的，然后继续训练，如果可以正常收敛的话说，那么就是没有问题的，如果还是不可以的话，那么就可以考虑看看是不是其他的原因

## 6. 不同的项目需要的数据格式不同，哪怕都是使用公共框架处理出来的数据集，要是想要在特定的项目上跑，还是需要做一下数据转化的

我们这里用worldgym和ctrl-world来举例一下，不同项目即使都使用公开框架，通常也有各自的数据 schema，不能只因为数据已经用 LeRobot 处理过，就直接保证能被 WorldGym 或 CTRL-World 使用。

lerobot这种框架，往往定义的是存储格式，如Parquet、JSON、视频文件、HDF5。

但是训练需要特殊的任务语义和字段语义，即使两个项目都读取 Parquet 文件，也可能要求：

* 不同的 observation/action 字段名；
* 不同的动作顺序、维度和单位；
* 不同的图像尺寸、颜色格式或相机视角；
* 不同的时间频率和帧对齐方式；
* 不同的 episode 起止标记；
* 不同的归一化统计量；
* 额外的 reward、language instruction 或 task id。

所以应该是需要写一个 adapter/converter，把 LeRobot 数据映射成 WorldGym 或 CTRL-World 需要的格式。
